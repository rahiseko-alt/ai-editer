# video-shorts — 動画を短く編集する（毎日運用）

ユーザーが動画を編集したいときに、この手順で対応する。
**すべてこのチャット画面で完結させる。ブラウザのUIや別サーバーは使わない。**

## 場所

このスキルが動くのは、セットアップ済みの video-shorts フォルダの中。
`pipeline.mjs` がある場所をカレントにして実行する（見つからなければユーザーにフォルダ場所を聞く）。

## 手順

### 1. 入力動画を確認する
- ユーザーが動画ファイル（mp4）のパスを示していなければ聞く。
- 動画が長い（10分超）場合は「文字起こしに少し時間がかかります」と先に伝える。

### 2. 素材導入ヒアリング（毎回・省略禁止）
ジョブ作成（次の手順3）の前に、次の項目を**1回のメッセージにまとめて**、選べる中身も添えて聞く。
1つ答えるたびに聞き返すと手数が増えて使いにくい（実際に3回やり直しになった事例あり）。
ユーザーが複数項目をまとめて答えたら、その場で全部受け取る。一部しか答えなかったときは、
**答えていない項目だけ**をまとめて聞き返す（答え済みの項目を再度聞かない）。
**このうち編集モード・字幕・向きはジョブ作成に渡す**（それ以外は `pipeline.mjs` の引数ではない）。
**デフォルトを勝手に決めてはいけない。前回の回答を引き継いで省略してもいけない（毎回聞く）。**
「おまかせで」「普通でいい」等の回答も、それ自体を明示の回答として扱ってよい（黙って決めるのとは違う）。

1. **編集モード**: 「話題毎」と「ダイジェスト」のどちらにするか。
   - `topic`（話題毎）: 大きなテーマ単位で漏れなく全区間に分割する。話題が少し変わるたびに区切らず、
     関連する内容はまとめて1区間にする。冒頭挨拶・締めの定型・機材確認等の本編でない箇所だけを除外し、
     それ以外の本編は必ずどれかの区間に含める（取りこぼし禁止＝全編カバー）。
   - `digest`（ダイジェスト）: 最も面白い・価値が高い・引きの強い箇所だけを複数抜粋し、1本に連結する
     （全カバーは不要）。台本の再構成・検証修正ループは**AI編集エージェントが自動で行う**（手順6参照）。
2. **1本あたりの長さ**: 「おまかせ」か「◯分くらい」か。
   - おまかせ＝素材と編集モードに応じて自動で決まる（1本が素材全体の1/3を超えないよう自動調整）。
   - 分数を指定した場合、レンダリング時に `--duration-min <分>` として渡す（手順7参照）。
     出来上がりはその±30%の幅に収まる（例: 3分指定なら2分6秒〜3分54秒）。ぴったりにはならない
     （区間は発話の切れ目に合わせて詰めるため）。
3. **字幕の有無**: 「付ける」か「なし」か。
   - 「付ける」の場合、続けてこの項目の中で**スタイルは「おすすめ」か「詳細を指定」か**を聞く。
     - 「おすすめ」＝以降a〜eは聞かない。既定スタイル(ワードハイライト・角ゴシック・白文字・
       黒縁取り・内側縁取りなし・背景帯なし)のまま手順7へ進む。
     - 「詳細を指定」の場合、次のa〜eを**1回のメッセージにまとめて**聞く(他の項目と同じく、
       一部しか答えなかったときは答えていない項目だけをまとめて聞き返す)。
       - a. **書体**: 角ゴシック／丸ゴシック／明朝体／手書き風／マーカー風 のいずれか
         (`node pipeline.mjs fonts` で一覧と説明を確認できる)。
       - b. **文字色**: 「既定(白)のまま」か「色を指定」か(`#RRGGBB`形式でのみ受け付ける。
         色名で答えられたら「#RRGGBB形式で教えてください」と聞き直す)。
       - c. **縁取り色(外側)**: 「既定(黒)のまま」か「色を指定」か(同じく`#RRGGBB`形式)。
       - d. **内側の縁取り(二重縁取り)**: 「なし」か「色を指定」か(同じく`#RRGGBB`形式。
         プレミアプロ風の袋文字にしたい場合はここで色を指定する)。
       - e. **背景帯**: 「なし」か「色を指定」か(`#RRGGBB`または`#RRGGBBAA`形式。
         帯を敷いて文字を読みやすくしたい場合に使う)。
     - a〜eの回答は `--sub`(ジョブ作成時)ではなく、レンダリング時に `--caption-font` /
       `--caption-fill` / `--caption-outline-color` / `--caption-inner` / `--caption-band`
       として渡す(手順7参照)。「既定のまま」「なし」と答えた項目はオプションを渡さない
       (省略時が既定の挙動になる)。
4. **出力の縦横**: 「縦」か「横」か。
   - 縦＝portrait（1080×1920・SNSリール等の縦枠向け）。
   - 横＝landscape（1920×1080・画面録画など細かい文字を残す用途向け）。
5. **書き出しの用途**: 「YouTube向け」「SNS向け」「X向け」「高画質保存」「軽くして共有」
   「標準（従来どおり・指定しない）」のいずれか。
   - 用途によって重さ（ファイルサイズ）が変わる。7分の動画がSNS投稿にもメール添付にも
     大きすぎた、という事例があったための項目（迷ったら「標準」でよい）。
   - レンダリング時に `--export <youtube|sns|x|archive|light|standard>` として渡す（手順7参照）。
<!-- mosaic:start -->
6. **顔モザイクの要否**: 「かける」か「かけない」か。
   - 写り込んだ人の顔を隠したいときに使う。**聞き忘れると素顔のまま納品される**ので必ず聞く。
   - 「かける」なら、次の手順3.5で対象者の指定に進む。

<!-- mosaic:end -->
### 3. ジョブ作成
手順2で聞いた**編集モード・字幕・向き**を渡す（`--mode` / `--sub` / `--orient` は**同時必須**。
どれか欠けると `pipeline.mjs` がエラーで停止する）。
```powershell
node pipeline.mjs init "<動画パス>" --mode <topic|digest> --sub <on|off> --orient <縦|横>
```
→ 表示された作業フォルダ `work/<id>` を控える。

<!-- mosaic:start -->
### 3.5. 顔モザイクの対象者を決める（手順2で「かける」と答えた場合だけ）

**ブラウザの画面は使わない。** 動画から顔を切り出した画像をフォルダへ出し、番号で答えてもらう。

```powershell
python src/face_choices.py "<動画パス>" work/<id>/faces
```
→ `work/<id>/faces/face-1.png`, `face-2.png` … が出力される（1人につき1枚・大きく写っている順）。

ユーザーにこう聞く（**1度に1つずつ**）:

1. 「動画に写っている方を `work/<id>/faces/` に切り出しました。フォルダを開いてご確認ください。
   この中で、**他の方と違う強さで隠したい方**はいますか？（番号／全員同じでよい）」
2. 番号の指定があれば: 「その方は強めと弱めのどちらにしますか？」

**指定が無くても、検出された顔には全員に既定のモザイクがかかる**ことを添える。
特定の人物の見分け（誰か）に失敗しても、顔として検出できていれば既定のモザイクはかかる。
ただし**顔検出そのものに見落としはあり得る**（横向き・逆光・手や物で隠れている等）。
とくに**小さく写っている人（遠くの通行人・群衆・引きの画）は隠れないと考えてよい**。
画面いっぱいが1920×1080のとき、顔の高さがおおむね30px（画面の高さの3%ほど）より小さいと
検出できず、素顔のまま残る。実測でも、出演者が大きく写るインタビューでは素顔の残りが
0.58%だったのに対し、遠くの人が多数写る引きの画では全コマに素顔が残った。
見落とされた顔にはモザイクがかからないので、**出来上がりは必ず確認してもらう**。
背景に人が写り込む映像では、モザイクだけに頼らず、その場面を使わない判断も併せて勧める。
特定の人を選ぶのは「他の人と強さを変えたい場合だけ」。

### 4. 文字起こし
```powershell
python src/transcribe.py "<動画パス>" work/<id>/transcript.json
```
- これは外部の音声認識AI（faster-whisper）が担当する。
- 初回だけモデルのダウンロードが走ることがある（数分）。失敗したらエラーを隠さずユーザーに見せる。

### 5. 区間選定の指示書を作る
```powershell
node pipeline.mjs select work/<id>
```
→ `work/<id>/llm-request.md` が出力される。

### 6. 区間を選ぶ
手順2で選んだ編集モードによって、ここでの作業が変わる。

- **`mode=topic` の場合（あなた＝Claude Code の仕事・APIキー不要）**:
  - `work/<id>/llm-request.md` を**自分で読む**。
  - 面白い・伸びそうな区間を選び、`work/<id>/llm-response.json` を**自分で書く**。
  - ルール:
    - **秒数（start / end）は絶対に出力しない**。後段が台詞を文字起こしに照合して秒数を自動確定する。
    - 返すのは `keepText`（残す台詞を文字起こしのまま）と `hook`（短い煽り文）だけ。
    - 形式: `{"segments":[{"keepText":"...","hook":"..."}, ...]}`（指示書の指定があればそれに従う）。
    - **明らかなNG・準備中（機材確認／音声テスト／「カットしよう」等の本編でないやり取り）は区間にしない＝捨てる**。本編の話題だけを残す。
  - これがこのシステムの核心。外部のLLM APIキーは不要で、あなた自身が選定役になる。
- **`mode=digest` の場合（手動作業は不要）**:
  - `pipeline.mjs select` を実行した時点で、内部の `digest-editor.mjs`（AI編集エージェント）が
    文字起こし全体を理解 → 台本を再構成（時系列の並べ替えを含む・声は素材のまま逐語） → 検証修正ループ、
    まで自動で行い `llm-response.json` を書き終えている。
  - **この場合は手順6での手動作業は不要**。そのまま次の手順7（レンダリング）へ進んでよい。

### 7. レンダリング
字幕on/offは手順2の回答が既に `work/<id>/state.json` に保存されているため、通常は追加オプション不要。
手順2で「1本あたりの長さ」「書き出しの用途」を聞いた回答を、ここで `--duration-min` / `--export` として渡す。
手順2で字幕スタイルの「詳細を指定」を選んだ場合は、a〜eの回答を `--caption-*` として渡す
（「おすすめ」を選んだ場合、または a〜e のうち「既定のまま」「なし」と答えた項目は渡さない）。
```powershell
node pipeline.mjs render work/<id> --duration-min <分> --export <youtube|sns|x|archive|light|standard> --caption-font <kaku|maru|mincho|hand|marker> --caption-fill <#RRGGBB> --caption-outline-color <#RRGGBB> --caption-inner <#RRGGBB> --caption-band <#RRGGBB>
```
- 「おまかせ」「標準」と答えた場合は、それぞれのオプションを省略してよい（既定の動きになる）。
- **ダイジェスト（`--mode digest`）のつなぎ目には、既定で「息継ぎの間」が入る**（`--breath`、既定0.7秒）。
  素材に元々あった無音（ルームトーン）を捨てずに前後へ残す方式なので、通常は指定不要。
  「もっとテンポよく詰めたい」と言われたら `--breath 0.3` のように短くし、
  「間は要らない・従来どおりでよい」なら `--breath off` を渡す。
  素材が元々その箇所に持っていた間より長い間は作らないので、指定を大きくしても不自然には伸びない。
```powershell
node pipeline.mjs render work/<id> --breath 0.3    # 詰めたいとき
node pipeline.mjs render work/<id> --breath off    # 間を付けないとき
```
- `--no-sub` は「手順2で答えた字幕設定を、この回だけ変更したい場合」の明示的な上書き用オプション。
```powershell
node pipeline.mjs render work/<id> --no-sub
```
→ `output/<id>/short-01.mp4`, `short-02.mp4` … と `output/<id>/candidates.json` が生成される。
- これは外部ツール（ffmpeg）が担当する。

### 7.5. 顔モザイクを焼く（手順2で「かける」と答えた場合だけ・省略禁止）

**ここを飛ばすと、設定を聞いたのに素顔のまま納品される。** 生成された各クリップに対して実行する。

```powershell
python src/apply_mosaic_cli.py "output/<id>/short-01.mp4" "output/<id>/short-01-mosaic.mp4"
```

手順3.5で対象者の指定があった場合は、その方の顔画像と強さを渡す:

```powershell
python src/apply_mosaic_cli.py "output/<id>/short-01.mp4" "output/<id>/short-01-mosaic.mp4" --target "work/<id>/faces/face-2.png" --strength 強め
```

- `--strength` は `強め` / `普通` / `弱め` のいずれか。指定しなければ `普通`。
- 指定した方以外の顔にも、既定の強さでモザイクがかかる。
- 音声は無変換でコピーされる（劣化しない）。
- **モザイク版が出来たら、以降の手順ではモザイク版（`-mosaic.mp4`）を候補として扱う**。
  元の（モザイク無しの）ファイルを客に渡さないよう注意する。

<!-- mosaic:end -->
### 8. 候補をチャットで提示して選別（チャット完結）
- `output/<id>/candidates.json` を読み、候補を**チャットに一覧表示**する。
  各候補ごとに: 番号 / hook文 / 尺（秒）/ confidence（区間照合の確からしさ）。
<!-- mosaic:start -->
- **顔モザイクを使った場合は、ここで必ず「隠しそこねが無いか」の確認を促す**。
  顔検出には見落としがあるため、機械の判断だけで納品できるとは伝えない。
<!-- mosaic:end -->
- 出力フォルダを開いて、ユーザーに実物を見てもらう:
```powershell
explorer "output\<id>"
```
- ユーザーに「残すもの（採用）の番号」を聞く（例: 「1,3,5」）。

### 9. 採用分をまとめて報告
- 採用された mp4 を `output/<id>/採用/` にコピーする。
<!-- mosaic:start -->
  **手順7.5でモザイクを焼いた場合は、必ず `-mosaic.mp4` の方をコピーする。**
  `candidates.json` には元のファイル名が並ぶので、番号からモザイク版へ読み替えること。
  ここで元ファイルを入れると、素顔のまま納品される。
<!-- mosaic:end -->

```powershell
mkdir "output\<id>\採用" 2>$null
<!-- mosaic:start -->
# 手順7.5でモザイクを焼いた場合はこちら
copy "output\<id>\short-01-mosaic.mp4" "output\<id>\採用\"

# モザイクを使わなかった場合はこちら
<!-- mosaic:end -->
copy "output\<id>\short-01.mp4" "output\<id>\採用\"
```
（採用番号の分だけ繰り返す）
- 最後に採用ファイルのパス一覧をユーザーに報告する。

## 失敗時のルール
- どれかのコマンドがエラー／EXIT 0 でない場合、「できました」と言わない。
- エラー出力をそのままユーザーに見せて止まる。ごまかさない（サイレントフェイル禁止）。

## やらないこと
- ブラウザの選別UI・ローカルサーバー（:8766）は使わない。すべてチャットとフォルダ操作で完結させる。
- 秒数をLLM（自分）に推測させない（手順6のルール）。
