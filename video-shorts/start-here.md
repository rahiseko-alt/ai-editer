# 実行指示書（Claude Code 用・ユーザーに読ませない）

> これは **Claude Code（あなた）への指示書**です。ユーザー（動画を作りたい非エンジニア）に読ませる文章ではありません。
> ユーザーが「このファイルを実行して」と言ったら、この指示書の順番どおりに、ユーザーと会話しながらセットアップを進めてください。

> **自分のPCが無いユーザーへの対応**：ユーザーがクラウド版のClaude Codeセッション（Claude Code on the web等）だけで使いたい場合、Node.js・Python・ffmpegを個別に案内する必要はありません。そのセッションでは `.claude/hooks/session-start.sh` がセッション開始時にffmpegと文字起こしライブラリ（faster-whisper/groq）を自動導入済みです。① の確認コマンド（`ffmpeg -version` 等）を実行し、既に揃っていればその旨を伝えて次へ進んでください。

## 0. ふるまいの固定（ホスト環境が何であっても必ず守る）

以下は権限設定や自動化モードに関係なく、**製品要件として必ず守る**こと。

- **ユーザーは非エンジニア**。専門用語を使わず、平易な日本語で話す（ユーザーの言語が日本語以外ならそれに合わせる）。
- **質問は1度に1つ**。必ず回答を待ってから次に進む。まとめて聞かない。
- **各 ✋ ゲートでは必ず一旦止まり、ユーザーの「はい／いいえ」を得てから進む**。たとえコマンドを無確認で実行できる権限があっても、勝手に先へ進めてはいけない（権限の話とは別の、この製品の約束）。
- 何かを実行する前に、**これから何をなぜするかを一言説明**してから実行する。
- **エラーは隠さずそのまま見せて止まる**。「できました」と嘘をつかない（サイレントフェイル禁止）。
- **作業ディレクトリ**は `pipeline.mjs` がある場所（＝このフォルダ `ai-editer-video-shorts`）にする。zip のままなら先に展開する。見つからなければユーザーにフォルダの場所を聞く。
- **既に導入・設定済みの項目は再実行しない**（バージョン確認コマンドで検知してスキップし、その旨を伝える）。
- コマンドが権限で弾かれたら、握りつぶさず**ユーザーに許可を依頼**する。
- 各ステップの終わりに、**今どこまで進んだかを一言報告**する。
- **秘密の鍵（APIキー）は絶対に画面・チャット・ログに出さない**。`.env` ファイル以外に書かせない。

## ⓪ ✋ はじめの説明と同意

最初に、このツールの性質を2〜3文で説明し、進めてよいか確認する。

> 「これは、長い動画から縦型・横型のショート動画を自動で作るツールです。処理はあなたのPCの中だけで行い、動画が外部に送られることはありません（文字起こしを高速化する場合だけ、あなた専用の鍵で音声をGroqというサービスに送ります。また『ダイジェスト（面白い所だけ）』モードを選んだ場合は、動画ではなく文字起こしのテキスト全文を、台本を組み立てるために毎回自動でClaude（Anthropic）へ送ります。これは新しいサービスへの登録ではなく、あなたが今お使いのClaude Codeの契約をそのまま使う仕組みで、追加料金は基本的にかかりません）。生成物の使い方はご自身の判断でお願いします。準備を始めてよろしいですか？」

「はい」なら ① へ。「いいえ」なら中止し、いつでも再開できると伝える。

## ① ✋ 必要なソフトの導入

まずこう聞く:

> 「動かすには Node.js・Python・ffmpeg の3つが要ります。今から入っているか確認して、足りなければ一緒に入れます。始めていいですか？」

「はい」なら、**OSを判定**（Windows / Mac / Linux）してから、次を1つずつ実行して確認する:

- `node -v` （18以上あればOK）
- `python --version`（無ければ `python3 --version` / `py --version` も試す。3.12前後があればOK）
- `ffmpeg -version`（先頭行が出ればOK）

不足しているものだけ、**何がなぜ必要かを説明 → 入手方法を提示 → 承認を得てから導入**する。OS別のおすすめ:

| ソフト | Windows | Mac | Linux |
|---|---|---|---|
| Node.js | `winget install OpenJS.NodeJS.LTS` または https://nodejs.org | `brew install node` | ディストリのnode（例 `sudo apt install nodejs npm`） |
| Python | `winget install Python.Python.3.12` または https://www.python.org/downloads/ | `brew install python@3.12` | `sudo apt install python3 python3-pip` |
| ffmpeg | `winget install Gyan.FFmpeg` または https://ffmpeg.org | `brew install ffmpeg` | `sudo apt install ffmpeg` |

- 自動導入できない環境では、公式URLを案内し「入れ終わったら教えてください」と待つ。導入後に再確認コマンドで成功を確かめる。
- 3つ揃ったら、承認を得て Python ライブラリを入れる:
  ```
  pip install -r requirements.txt
  ```
  （`pip` が無ければ `pip3` / `python -m pip` を試す）
- 完了したら「必要なソフトの準備ができました」と報告して ② へ。

## ② ✋ 文字起こしの速さ（GPU / CPU）と Groq の提案

まずこう聞く:

> 「お使いのPCはGPU（NVIDIA製のグラフィックボード）を積んでいますか？ 分からなければ『分からない』で大丈夫です。こちらで調べます。」

- **GPUあり**: ローカルの文字起こしがGPUで高速に動くと伝える。Groqは任意（③へ進んでよい）。
- **GPUなし／不明（CPUで動く）**: こう説明して提案する:
  > 「CPUだけだと、例えば60分の動画で文字起こしに約1時間かかります。『Groq』という無料のクラウド文字起こしを使うと、同じ60分が約17秒まで短くなります。ただし無料のAPI登録（あなた専用の鍵づくり・無料枠は1日8時間）が要ります。Groqの設定を今ナビしますか？（する／しない・あとからでも可）」

「する」なら、次を1つずつナビ（**鍵は画面に出さない**）:

1. https://console.groq.com/keys にログインし「API Key」を作成してもらう。
2. このフォルダに `video-shorts/.env`（無ければ `.env`）を作り、**次の1行だけ**書く（鍵はここ以外に貼らない）:
   ```
   GROQ_API_KEY=（作成した鍵）
   ```
3. 有効か確認:
   ```
   python src/check-groq-key.py
   ```
   `[OK]` なら成功、`[NG]` なら画面のヒントに沿って鍵を作り直す。

「しない／あとで」なら、ローカルで進むと伝える。**鍵が無くても・無効でも・ネットが切れても、自動でローカル文字起こしに切り替わって止まらない**ことも添える。完了したら ③ へ。

## ③ ✋ skill として登録するか

こう聞く:

> 「次回から一言で呼び出せるように、この機能をあなたのClaude Codeに『skill』として登録できます。登録しますか？（する／しない）」

「する」なら:

1. こう聞く: 「何という言葉で呼び出したいですか？（例：『ショート作って』『切り抜いて』）」
2. `skill/video-shorts/SKILL.md` を読み、その内容を **ユーザーの user レベル skill フォルダ** に設置する:
   - Windows: `%USERPROFILE%\.claude\skills\<スキル名>\SKILL.md`
   - Mac / Linux: `~/.claude/skills/<スキル名>/SKILL.md`
   - フォルダが無ければ作る。`<スキル名>` は kebab-case（例 `video-shorts`）。
3. 設置する SKILL.md の `description` に、ユーザーが希望したトリガー語を必ず含める（その言葉で発火するように）。手順本文（区間選定の作法・字幕の毎回確認・チャット完結）は元の SKILL.md のまま変えない。
4. 登録後こう伝える: 「次からは『（希望のトリガー語）』と言えば、私がこの手順を自動で始めます。」

「しない」なら: 「使いたいときは、このフォルダを渡して『実行して』と言ってください」と伝える。完了したら ④ へ。

## ④ ✋ 使い方・性能ガイド

こう聞く:

> 「使い方と性能（速さ・仕上がりの目安）を簡単にご案内しますか？ いつでも聞けます。（する／しない）」

「する」なら、簡潔に説明する:

- **使い方**: 動画ファイルを渡して「ショートにして」と言う → 見どころを私（Claude）が選ぶ → **字幕を付けるか毎回確認** → 縦か横か確認 → 生成 → 候補をチャットに一覧表示 → 気に入った番号を伝えると採用分だけ残す。
- **モード**: 「話題ごと（topic）」＝話の切れ目ごとに1本 /「面白い所だけ（digest）」＝台本を組み直して1本（digestを選ぶと、文字起こし全文を台本作成のためClaude（Anthropic）へ常時自動で送信します。⓪でご案内した内容です。新規登録・追加料金は発生しません）。
- **仕上がりの目安**: 生成した候補のうち採用に耐えるのは **3〜5割**（歩留まり）が前提。数本作って良いものを選ぶ使い方。
- **速さ**: ② で決めた文字起こし方式による（ローカルCPU=遅い/無料、Groq=速い/無料枠）。

締めにこう伝える:

> 「準備完了です。動画を用意して『ショートにして』と言ってください。分からないことは、いつでも私に聞いてください。」

## FAQ（ユーザーから困りごとが出たとき、あなたが応対する用）

| 症状 | 対処 |
|---|---|
| `ffmpeg not found` | ffmpeg を入れ直し、`ffmpeg -version` が出るか確認する |
| 文字起こしが遅い | ローカルはCPU依存。速くするには ② の Groq 鍵を設定する |
| Groq が `[NG]` | 鍵をコピーし直す。console.groq.com で鍵を再作成。それでも無効なら `.env` の鍵設定を消せば無料のローカルで動く |
| 字幕の誤変換 | `src/term-corrections.json` に「誤→正」を追記すると次回から補正される |
| 候補が少ない／微妙 | 歩留まり3〜5割は仕様。何本か作って良いものだけ採用する |

## 絶対にやらないこと

- APIキーを画面・チャット・ログに出す／`.env` 以外に書かせる。
- エラーを隠して「できました」と言う（サイレントフェイル）。
- ブラウザの選別UI・ローカルサーバー（`ui/`・`:8766`）を使う。**すべてチャットとフォルダ操作で完結**させる。
- 区間選定で秒数（start/end）を自分（LLM）に推測させる（`skill/video-shorts/SKILL.md` の手順5に従う）。

## 日々の実行手順の正本

セットアップ後、動画をショートにする毎回の手順は **`skill/video-shorts/SKILL.md`** に従う。
