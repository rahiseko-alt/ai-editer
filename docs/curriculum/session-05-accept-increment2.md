## 2. スライド構成

1. **今日のゴール**：増分2の独立受入（コマ4と同じ型）と、要件変更があれば工数へ即時反映する回。
2. **独立受入の手順**：コマ4と同じ（受入条件を読み上げる→再現手順で確認→合否記録）。
3. **要件変更の見分け方**：発注時の受入条件から範囲がずれていないかを確認する。
4. **概算アプリDで再計算**：範囲が変わった場合、工数・期間・コストをレンジで再算出する。
5. **B2への接続**：要件変更は黙って混ぜず、B2の付け足し／定義変更の型で起票する。

---

## 3. 進行台本

### 0-5分：目的の確認

```text
今日は増分2の独立受入と、もし発注内容が途中で変わっていれば、その影響を数字で示します。
```

### 5-30分：独立受入を実行する（コマ4と同じ手順）

- 受入条件を読み上げる → 再現手順で確認する → 合否を記録する。

### 30-45分：要件変更の有無を確認する

```text
発注したときと比べて、範囲や前提が変わったところはありますか。
```

- 変わっていれば、B2 §2（付け足し）または §3（定義変更）のどちらの型かを見分ける。

### 45-55分：概算アプリDで再計算（該当時のみ）

- `apps/web/app/estimate` の「要件変更」欄に変更分の三点見積りを入力し、変更前後の工数レンジと差分を出す。

### 55-60分：承認

**承認の問い**

```text
この受入結果（＋変更があればその影響）を確定してよいですか。
```
