# C-1a: コマ1 リモート初回教材（スライド構成＋進行台本）

> ロードマップ葉 **C-1a** の途中成果物。初回90分をリモートで実施し、関係者と問題を構造化して、
> 次の **C-1b（顧客の原子ロードマップ確定）** に接続するためのスライド構成と進行台本を1つにまとめる。
>
> **本書で満たす範囲**：コマ1のスライド一式と進行が準備されていること。
> **まだ満たさない範囲**：リモート通しリハーサルの記録。C-1a の evidence は、公開URL/録画リンクで通しリハ成立を確認してから埋める。

---

## 0. コマ1の到達点

コマ1の終了時点で、顧客が承認した原子レベルの解決ロードマップが1枚に確定している。
各葉は「独立して落ちうる受入事実ちょうど1つ」まで割られ、各葉に受入条件と検証方法がある。

## 2. スライド構成

### Slide 1: 今日のゴール

- 今日やることは「解く作業」ではなく「解く対象を1枚に確定する」こと。
- 最後に、受入条件つきの原子ロードマップを全員で承認する。
- 承認したロードマップが、2回目以降の発注・受入・変更管理の正になる。

**講師メモ**：ここで「今日は結論を急がず、構造を固める回です」と明言する。

### Slide 2: 90分の流れ

| 分 | パート | 目的 |
|---:|---|---|
| 0-10 | 合意形成 | ゴール・役割・今日の決め方を揃える |
| 10-30 | 状況を広げる | リッチピクチャで関係者・出来事・制約を出す |
| 30-45 | 解くべき問題を定義する | CATWOE / 根本定義で焦点を決める |
| 45-70 | 原子分解する | イシューツリーで受入事実まで割る |
| 70-82 | 優先順位を決める | 最初に検証する葉を選ぶ |
| 82-90 | 承認する | ロードマップ、宿題、未決事項を確定する |

### Slide 3: 決め方のルール

- 1つの葉は、1つの受入事実だけを表す。
- 受入条件は、後から第三者が確認できる形で書く。
- 迷ったら「これが欠けても別の葉は受け入れられるか」を問う。
- 途中で追加が出たら、黙って混ぜずに未決事項か追加葉として扱う。

### Slide 4: 状況を広げる問い

- 誰が困っているか。
- 何が起きると損をするか。
- どのデータや現物で確認できるか。
- 変えられるものと変えられないものは何か。
- 期限、予算、人手、外部制約は何か。

### Slide 5: CATWOEで問題の枠を決める

| 観点 | 問い |
|---|---|
| Customer | 変化の影響を受ける人は誰か |
| Actor | 実際に変える人は誰か |
| Transformation | 何を何に変えるのか |
| Worldview | なぜその変化が価値になるのか |
| Owner | 止める/承認する権限を持つ人は誰か |
| Environment | 変えられない制約は何か |

### Slide 6: 根本定義

次の形で1文にする。

```text
＜誰が＞、＜制約の中で＞、＜何を＞から＜何へ＞変えることで、＜誰にとっての価値＞を実現する。
```

### Slide 7: イシューツリー化

- 根本定義を頂点に置く。
- 子は「成立に必要な条件」で割る。
- 工程ではなく、満たすべき状態で書く。
- 葉は検証可能な1事実になるまで割る。

### Slide 8: 葉の書式

```text
葉ID:
  うれしい状態:
  受入条件:
  検証方法:
  必要なデータ/現物:
  未決事項:
```

### Slide 9: 優先順位づけ

次の順で最初の葉を選ぶ。

1. 解決の定義に直結する。
2. 早く検証できる。
3. 失敗したときに学びが大きい。
4. 他の葉の依存元になっている。

### Slide 10: 承認チェック

- ロードマップの頂点が、顧客の言葉で書かれている。
- 各葉に受入条件と検証方法がある。
- 最初に検証する葉が1つ選ばれている。
- 次回までの宿題と担当が決まっている。
- 未決事項が、作業に混ざらず別枠に置かれている。

## 3. 90分進行台本

### 0-10分: 合意形成（Slide 1〜2を表示）

**講師の言い出し**

```text
今日は解決策を決め切る回ではなく、解く対象を全員で同じ1枚に固定する回です。
終わりには、受入条件つきのロードマップを承認し、次回までに何を確認するかを決めます。
```

**確認すること**

- オーナーは誰か。
- 今日の承認者は誰か。
- 90分で決める範囲と決めない範囲は何か。

### 10-30分: 状況を広げる（Slide 4を表示）

**進め方**

1. 参加者に「困っている出来事」を短文で出してもらう。
2. 出た出来事を、人・業務・データ・制約に分けて並べる。
3. 事実と解釈を分ける。

**止めるサイン**

- 解決策の議論が始まったら、「今は状況の地図に戻します」と戻す。
- 具体例がない抽象語は、「最後に起きた実例は何ですか」と聞く。

### 30-45分: 解くべき問題を定義する（Slide 5〜6を表示）

**進め方**

1. CATWOE の6観点を1つずつ埋める。
2. 根本定義の1文にまとめる。
3. 参加者に「この問題を解けば価値が出るか」を確認する。

**承認の問い**

```text
今日のロードマップは、この1文を頂点に作ってよいですか。
```

### 45-70分: 原子分解する（Slide 7〜8を表示・本コマの中核＝25分）

**時間配分の目安**

| 分 | やること |
|---:|---|
| 45-52 | 根本定義の直下に、成立に必要な状態を3〜5個出す |
| 52-65 | 各状態をさらに割り、葉ごとに受入条件・検証方法を書く（Slide 8の書式） |
| 65-70 | 全体を見渡し、粒度が不揃いな葉を下記の言い換えで揃える |

**進め方**

1. 根本定義を頂点に置く（Slide 7）。
2. 成立に必要な状態を3〜5個に割る。
3. 各状態を、受入事実が1つになるまでさらに割る。
4. 各葉に受入条件と検証方法を書く（Slide 8の書式を使う）。

**講師の言い出し**

```text
ここからは、さっき決めた1文（根本定義）を頂点に置いて、「これが成り立つには何が真である必要があるか」を枝に割っていきます。
枝は「やること（作業）」ではなく「なった状態」で書いてください。作業と状態は混ざりやすいので、迷ったら私に聞いてください。
```

**よくある誤りと、その場での言い換え**

- **作業を状態と書いてしまう**
  - 顧客の発言例：「営業リストを整理する」
  - 講師の言い換え質問：「それをやり終えたとき、何が"真"になっていますか？」
  - 言い換え後の葉：「営業リストが、重複なく最新の状態になっている」
- **粒度が粗く、独立した受入事実が2つ以上混ざる**
  - 顧客の発言例：「集客と接客の両方を改善する」
  - 講師の確認文：「集客だけ改善できて接客がまだでも、それは"半分の成果"として受け入れられますか？　それとも両方揃わないと意味がないですか？」
  - 「半分でも受け入れ可」なら独立した2つの葉に割る。「両方揃って初めて意味がある」なら1葉のまま残す。
- **抽象語で止まり、検証可能な形にならない**
  - 顧客の発言例：「もっと効率的になる」
  - 講師の言い換え質問：「それが実際に起きた／起きていない、と誰が見ても同じ判定になる書き方にできますか？　例えば数字や、はい/いいえで答えられる形にすると？」

**講師の確認文（葉を書くたびに1つずつ）**

```text
この葉は、後から第三者が Yes/No で確認できますか。
この葉が未達でも、別の葉は独立に受け入れられますか。
これは「やること」ではなく「なった状態」で書けていますか。
```

### 70-82分: 優先順位を決める（Slide 9を表示）

**進め方**

1. すべての葉に「価値直結」「検証の早さ」「依存元」「不確実性」を簡単に付ける。
2. 最初に検証する葉を1つ選ぶ。
3. 次回までに必要なデータ・現物・担当を決める。

**講師の言い出し**

```text
全部の葉を同時には検証できません。今出た葉から、最初に手をつける1つをこれから選びます。
```

**葉ごとに問いかける4つの確認文（Slide 9の観点）**

```text
この葉が欠けると、解決の定義に届きませんか。（価値直結）
これは次回までに検証できますか。（検証の早さ）
これがダメだと分かったら、他の何が変わりますか。（依存元）
これは、やってみないと結果が読めない部分ですか。（不確実性）
```

**確認すること**

- 選んだ葉に、担当者と次回までの期限が付いている。
- 選ばれなかった葉も「捨てた」のではなく「後回し」として残っている。

**承認の問い**

```text
最初に検証するのはこの葉でよいですか。他に急ぐべきものはありませんか。
```

### 82-90分: 承認する（Slide 10を表示）

**読み上げるもの**

- 頂点の問題定義。
- 最初に検証する葉。
- 次回までの宿題。
- 未決事項。

**最後の承認文**

```text
このロードマップを、次回以降の発注・受入・変更管理の正として扱ってよいですか。
```

## 5. 通しリハで観察すること

C-1a の evidence に使う通しリハでは、少なくとも次を観察する。

- 90分以内に、Slide 1〜10 の流れを止めずに通せる。
- 参加者役が、根本定義と葉の受入条件を理解して言い換えられる。
- 葉が2事実以上を含んだとき、講師がその場で割り直せる。
- 未決事項と追加要望を、作業に混ぜずに別枠へ退避できる。
- 最後に、ロードマップ・宿題・未決事項の3点を読み上げて承認できる。
