# D2: リモート通しデモ 進行台本・チェックリスト

> ロードマップ葉 **D2** の evidence 収集用。
> `verify`：「リモート操作の通しデモ記録（公開URL/録画リンク）が結果共有まで成立することを確認する」。
>
> **本書で満たす範囲**：実演者が迷わず辿れる進行台本と観察チェックリストの用意。
> **まだ満たさない範囲**：実際のリモート画面共有デモの実施と記録。入力欄の不具合修正（draft入力を
> `type="text"`/`inputMode="decimal"` で保持する変更）を含む最新コミットのマージと、それに対応する
> 本番デプロイが完了していることを確認したうえで、本番URL（`https://cc-v2-web.vercel.app/estimate`）で
> 本書の手順を実演し、録画リンクまたは通し記録を D2 の evidence に書き込む。
> **URL到達だけでは不十分**：`https://cc-v2-web.vercel.app/estimate` が200を返すことは「デプロイが存在する」
> ことしか示さず、「入力欄修正を含む最新版がデプロイされている」ことは示さない（古いデプロイのままでも
> 同じURLで200が返りうる）。デモ実施の直前に `git rev-parse origin/main` 等で対象commit SHAを1つ確定・記録し
> （比較対象を「実施時点のmain HEAD」という動く基準にしない）、Vercelダッシュボードまたは `vercel ls`/
> デプロイAPIで**本番デプロイに紐づくcommit SHAが、その確定したSHAと一致すること**を確認する。

## 2. 進行台本

### 0. 画面共有を開始する

講師役が `/estimate` を開き、画面を共有する。

```text
これから工数・コストの概算アプリを一緒に操作します。
入力を変えるとその場で結果が再計算されるので、画面を見ていてください。
```

### 1. 工数（person-day）を入力する

- 「工数」欄の楽観・最頻・悲観に **3 / 5 / 10** を入力する。
- 結果セクションに工数レンジ `3.0 〜 10.0 人日（期待値 5.5）` と信頼度が即時表示されることを確認する。

**観察ポイント**：入力のたびに結果が再計算され、画面共有先の受講者役からも変化が見えるか。

### 2. 単価・稼働（任意）を入力する

- 「単価（1人日あたり）」と「稼働能力（人日/暦日）」を入力する。
- 結果にコストレンジ・期間レンジが追加表示されることを確認する。

**観察ポイント**：任意項目を後から埋めても、既存の工数レンジ表示が崩れずコスト・期間が追加されるか。

### 3. 要件変更を試す（追加）

- 「要件変更」の種別を「追加」に切り替える。
- 変更分の工数（楽観・最頻・悲観）に **1 / 2 / 3** を入力する。
- 「変更前」工数が `5.5` 人日、「変更後」工数が `7.5` 人日、「差分」が **`+2.0` 人日** と表示されることを確認する
  （基準3/5/10・変更分1/2/3の組み合わせでの期待値。プラスかつ明確に0でない値になる）。

**観察ポイント**：差分の符号・値が入力と整合しているか、受講者役に説明できるか。

### 3'. 要件変更を試す（削減）

- 「要件変更」の種別を「削減」に切り替える（工数入力は3/5/10のまま）。
- 変更分の工数（楽観・最頻・悲観）に **1 / 2 / 3** を入力する。
- 「変更前」工数が `5.5` 人日、「変更後」工数が `3.5` 人日、「差分」が **`-2.0` 人日** と表示されることを確認する
  （マイナスかつ明確に0でない値になる）。

**観察ポイント**：追加(+2.0)と削減(-2.0)で符号が正しく反転しているか。

### 4. 結果共有を確認する

- 画面共有のまま、受講者役に「今の工数レンジと信頼度を読み上げてください」と聞く。
- 受講者役が画面上の数値をそのまま読み上げられることを確認する。

```text
今の画面で、工数・コスト・期間・信頼度が見えていますか。読み上げてもらえますか。
```

## 3. 成果物チェックリスト（evidenceに書く前に確認）

- [ ] 本番URL（`https://cc-v2-web.vercel.app/estimate`）が実際に開けている（プレビューURLではない）。
- [ ] デモ実施の直前に確定したcommit SHA（`git rev-parse origin/main` 等）を記録している。
- [ ] 本番デプロイに紐づくcommit SHAが、上記の確定したSHAと一致することを確認している
      （Vercelダッシュボードのデプロイ詳細、またはデプロイAPI/CLIで確認し、両方のSHAをevidenceに記録する）。
- [ ] 画面共有下で、工数の入力→結果の即時反映が実演できている。
- [ ] 単価・稼働の追加入力でコスト・期間が追加表示されている。
- [ ] 要件変更「追加」（基準3/5/10・変更分1/2/3）で差分 `+2.0` が表示されている。
- [ ] 要件変更「削減」（基準3/5/10・変更分1/2/3）で差分 `-2.0` が表示されている。
- [ ] 受講者役が画面上の結果を読み上げて共有できている。
- [ ] 録画リンク、または通し実施の記録（実施日時・参加者・上記チェック結果）が残っている。

チェックが全て埋まったら、記録（録画リンクまたは実施記録の公開URL）を
`docs/roadmap.html` の D2 の `evidence` に書き込む。
