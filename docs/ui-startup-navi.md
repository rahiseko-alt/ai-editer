# UI起動ナビ（この手順の全文をステップ0から提示する）

マスターから「UIで編集したい」「画面を出したい」「動かしたい」に類する指示を受けたら、
**このファイルの手順をそのまま、ステップ0から全文提示する**（AGENTS.md の規律）。
その場で組み立てない。要約しない。「前と同じです」で済ませない。

**移動を伴う手順には必ず移動するコマンドを書く。** 2026-08-15、これを怠って
`ERR_CONNECTION_REFUSED` を起こした（`docs/failures.md` 参照）。

**2026-08-19 変更：ターミナルは2枚になった。** 中継サーバーに加えて、投入されたジョブを
自動で走らせる常駐ワーカー（`server/job-worker.mjs`）を起動する。以前は誰かが手で
`node src/edit-job.mjs <jobId>` を叩くまで何も起きず、UI が待ち続けていた。

**2026-08-19 追加：ステップ4「Claude が見張りを張る」が要る。** ターミナル2枚は**マスターが開くもの**、
見張りは**Claude が自分で張るもの**で、別物。ワーカーは文字起こしまでしか自動実行せず、
その完了はワーカーの黒い画面に出るだけで Claude には届かない。見張りが無いと、投入しても
Claude が気づかず、UI が回り続ける（同日、実際にそれで1本無駄にした）。

## ふつうはこれだけ：`起動.bat` をダブルクリックする

エクスプローラーで `C:\Users\user\ai-editer` を開き、**`起動.bat` をダブルクリックする。**

これ1回で、前回の残りの片付け・サーバー起動・ワーカー起動・ブラウザを開くところまで終わる。
黒いウィンドウが2つ開くが、**閉じないこと**（閉じると止まる）。

> **`起動.bat` に見張り（下のステップ4）は含まれない。** bat が終わっても起動は半分で、
> Claude が見張りを張るまで、投入した動画に誰も気づけない。
> bat が「起動しました」と表示するのは**ウィンドウ2枚が上がった**という意味だけである。

- 「AI-Editer サーバー」… 1行だけ出る。見なくてよい。
- 「AI-Editer 編集の進行」… 編集の進み具合（`[1/7] 文字起こし中…`）が出る。**困ったらここを見る。**

ブラウザが自動で開かない場合だけ、手で `http://127.0.0.1:5178` を開く。

> `起動.bat` は **Shift-JIS で保存すること**。UTF-8 で書くと cmd が日本語を読めず
> `'ー]' is not recognized as ...` で壊れる（2026-08-19 に実際に踏んだ）。

以降のステップ0〜3（ターミナル2枚とブラウザ）は、`起動.bat` が動かないときの手動の代替。

**ただしステップ4（Claude の見張り）は代替ではない。`起動.bat` を使った場合も必ず実行する。**
bat はウィンドウを2枚開くだけで、見張りは張らない（意図的にそうしている。理由は
`video-shorts/server/watch-jobs.mjs` 冒頭の「なぜ 起動.bat の3枚目のウィンドウにしないのか」）。

## ステップ0：すべてのターミナルを閉じる

開いているターミナル・PowerShell をすべて閉じる。前回の残りが動いていると、
ポート 5178 が塞がって新しいサーバーが起動できない。

## ステップ1：1枚目のターミナルを開き、中継サーバーを起動する

新しい PowerShell を開いて、次を**そのまま**実行する（移動を含む）。

```bash
cd C:\Users\user\ai-editer\video-shorts; node server/index.mjs
```

次の1行が出れば成功。**このターミナルは閉じない。**

```
[video-shorts server] listening on http://127.0.0.1:5178
```

## ステップ2：2枚目のターミナルを開き、ワーカーを起動する

**別の** PowerShell を新しく開いて、次をそのまま実行する。

```bash
cd C:\Users\user\ai-editer\video-shorts; node server/job-worker.mjs
```

次の2行が出れば成功。**このターミナルも閉じない。**

```
[worker] 見張りを開始します: C:\Users\user\ai-editer\.runtime\chat-inbox.jsonl
[worker] 起動前にあった N 件は処理しません（起動後に投入されたぶんだけ実行します）
```

> ⚠ **この `[worker] 見張りを開始します` は、ステップ4の「Claude の見張り」とは別物。**
> こちらは**ワーカーが投入フォルダを見て文字起こしを起動する**という意味。
> これが出ていても、ステップ4はまだ終わっていない。同じ「見張り」という語だが主体も対象も違う。

編集の進行（`[1/7] 文字起こし中…` など）はこの2枚目に出る。詰まったときはここを見る。

## ステップ4：Claude が見張りを張る（マスターの操作は不要・Claude がやる）

**このステップは Claude 側の作業。** ターミナルは増えない。Claude が `Monitor` ツールで
次を **`persistent: true`** で常駐させる。

```bash
cd /c/Users/user/ai-editer/video-shorts && node server/watch-jobs.mjs
```

`見張り開始: ...` の1行を**実際に受け取るまでは、張れていないものとして扱う**。
以後、投入された動画の文字起こしが終わると `選定待ち <jobId> 文節<N> 指示「…」` が Claude へ届く。
失敗・中止・停滞（投入から15分進んでいない）も同じ経路で届く。

**Claude 向けの注意（ここを外すと「張ったつもり」になる）**

- `Monitor` が使えるツール一覧に無い場合は、`ToolSearch` で `select:Monitor` を読み込んでから使う。
- **`Bash` のバックグラウンド実行で代用してはいけない。** 常駐プロセスは終了しないので、
  1行ごとの通知が届かない（＝投入に気づけない。まさに直したかった不具合が再発する）。
- **義務は「誰が起動したか」に依存しない。** マスターが自分で `起動.bat` を押した場合も、
  既に動いていた場合も、UIが上がっていると分かった時点で他の何より先に張る。
- 張れていない状態で「立ち上げました」「準備できました」「投入してください」
  「お待ちしています」のいずれも言ってはいけない（`.claude/skills/video-edit-checklist` が正）。

## ステップ5：編集する

1. 左上の枠に動画をドラッグ&ドロップ（またはクリックして選択）
2. 一覧に出たサムネイルをクリックして選ぶ
3. 右側で 縦横比 / 字幕の有無 / 目標の尺 を設定する
4. 下の欄に指示を入れる（空でもよい。空なら自動で判断する）
5. 「実行」を押す

## ステップ6：結果を見る

- 完成すると画面に動画が出る。
- その下に **「この指示で編集しました／反映した内容／反映できなかった項目」** が出る。
  **反映できなかった項目（黄色）が要点。** BGM の追加のように、このツールが原理的に
  できない指示はここに理由付きで出る。
- ダウンロードは「書き出し」から。

## 終わるとき

2枚のターミナルでそれぞれ `Ctrl+C`。Claude 側は見張り（ステップ4）を `TaskStop` で止める。
（見張りが起動の一部である以上、終了手順にも出てくるのが筋である）

## 出力を見る前に原因を言わない

症状が説明できないうちは対処を提案しない。まず観測できる形にする
（2026-08-15、原因を確かめずに対処を2回続けて指示して外している）。

| 症状 | まず見る場所 |
|---|---|
| ブラウザが `ERR_CONNECTION_REFUSED` | 1枚目のターミナル。listening の行が出ているか |
| 実行を押しても何も起きない・待ち続ける | 2枚目のターミナル。`受け付けました:` が出ているか |
| 文字起こしは終わったのに先へ進まない | **Claude が見張り（ステップ4）を張っているか。** 張っていないと誰も気づかない |
| 途中で失敗する | 2枚目のターミナルの最後の `[n/7]` がどこで止まったか |
| 指示が効いていない気がする | 画面の反映報告と `.runtime/work/<jobId>/decision.json` |

## 前提（満たしていないと遅い・動かない）

- `video-shorts/.env` に `GROQ_API_KEY` があること。無いと文字起こしがローカル実行になり大幅に遅い。
- `ffmpeg` / `ffprobe` にパスが通っていること。
- Python が入っていること（文字起こしに使う）。
