# F1-a: コマ間の受講者フォローガイド

> ロードマップ葉 **F1-a** の成果物。コマとコマの間（週1回・約7日間の空き）に、講師が受講者（顧客）を
> フォローする手順を、声かけのタイミング・文面・進捗確認の基準を含めて定義する。
>
> - コマ内の進行は **B1**（各回の目的・到達点）・**C-1b**（初回の進行）が正。本ガイドは**コマ間**（回と回の間）の
>   実務だけを扱う。
> - 変更（付け足し・定義変更）の扱いは **B2** が正。フォロー中に変更の兆し（顧客の要望変化等）を検知したら、
>   本ガイドの§4に従って起票し、B2の再凍結イベントへ回す（フォロー担当が黙って判断しない）。

---

## 1. 目的

コマ間で受講者が放置されると、①増分の受入判断に必要な情報（現場での使用感等）が抜ける、②途中脱落が起きる、
③次コマ冒頭で状況確認にコマ内時間を浪費する、という3つの事故が起きる。本ガイドはこれを防ぐ最小手順を定める。

## 2. フォローのタイミングと内容

| タイミング | 目的 | 内容 |
|---|---|---|
| コマ終了直後（当日中） | 合意事項の齟齬を早期に潰す | そのコマで決まった到達点・次回までの宿題（F1-b）・増分の発注内容（該当コマのみ）を1通で要約送付 |
| コマ間中間（3〜4日後） | 増分の進捗・障害の早期検知 | 「別チームからの増分は順調か」「宿題（B3該当項目）で詰まっていないか」を1問だけ聞く短い連絡 |
| 次コマ前日 | 次コマの受入判定に必要な材料を揃える | 増分の納品物（あれば）・宿題の結果を、次コマ開始前に共有してもらうよう依頼 |

- **声かけは常に「進捗を聞く」形にし、「順調ですか」で終わらせない**：中間連絡・前日連絡は必ず具体的な確認事項
  （上表「内容」列）を1つ以上含める。抽象的な確認だけだと問題の兆候を見逃す。
- **返信が無い場合**：次コマ前日連絡に24時間以上応答が無ければ、コマ開始1時間前を目安に電話等の同期手段で
  最終確認する（次コマ冒頭を手戻りゼロで始めるため）。

## 3. 進捗確認の基準（何を「順調」とみなすか）

フォロー担当は次の2点を確認できていれば「順調」と記録してよい。どちらか欠けば§4へ。

1. 直近コマで発注した増分（該当があれば）の**納品予定に変化がないか**（B2 §1「受領時の必須手順」の前提）。
2. 直近コマの宿題（F1-b）が**着手されているか**（未着手でも理由が分かれば可。無反応は不可）。

## 4. 変更・懸念の検知時（B2への接続）

フォロー中に次のいずれかを検知したら、フォロー担当は**その場で判断せず**、B2 §2（付け足し）または §3
（定義変更）の起票フローに乗せる：

- 受講者から「対象範囲を広げたい／狭めたい」等のスコープ変更の申し出
- 受講者から「目標値（定義100%）を変えたい」という申し出
- 増分の遅延や、受入条件について発注側・受託側の認識がズレている兆候（B2 具体例C相当）

起票は次コマの冒頭を待たず、検知した時点で `docs/roadmap.html` の該当葉へ起票し、次コマまでに再凍結イベント
（B2 §4）の①改訂を済ませておく（次コマ内で①からやり直すと時間が足りないため）。

## 5. チェックリスト（フォロー担当が毎コマ間で使う）

- [ ] コマ終了直後、合意事項＋宿題＋発注内容を要約送付した。
- [ ] 中間連絡で、増分進捗と宿題の詰まりを具体的に確認した。
- [ ] 前日までに、次コマの受入判定に必要な材料（納品物・宿題結果）を受け取った。
- [ ] 応答が無い場合、次コマ開始1時間前までに同期手段で確認した。
- [ ] 変更・懸念の兆候があれば、その場でB2の起票フローに乗せた（次コマまで待たなかった）。

---

## トレーサビリティ

- 本ガイドは **B2**（変更管理の型）を、コマ間の受講者対応という実務に落としたもの。
- 宿題そのものの設計方法は **F1-b**、別チーム開発への受け渡し確認は **F1-c** が正。本ガイドはそれらと合わせて
  **F1**（コマ間の伴走ガイド）を構成する。
