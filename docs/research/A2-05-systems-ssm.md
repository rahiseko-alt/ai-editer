# A2-⑤: システム思考・ソフトシステム方法論（SSM / 問題構造化手法 PSM）の深掘り

> ロードマップ葉 **A2-5** の成果物。採用領域⑤から、教材に組み込む**原則・道具・落とし穴**を出典つきで抽出する。
> 本領域は**初回の問題構造化（C-1b）**と骨格（B）を支える。ソフト（人・利害が絡む）な問題を、決めつけず構造化してから解く型。

## 原則（何を使うか）
- **ソフト問題とハード問題を分ける**：SME の課題は目的・利害・前提が食い違う"ソフト"な問題。定義済みの問題を最適化するのでなく、**関係者と一緒に問題状況を学習・構造化する**（Checkland, 1981『Systems Thinking, Systems Practice』）。
- **人と組織は問題解決から切り離せない**：問題認識の背後にある前提・メンタルモデルを表に出すことが解決の一部。
- **7段階モデル**：①問題状況の把握 → ②リッチピクチャ描画 → ③根本定義（root definition）→ ④CATWOE → ⑤概念モデル化 → ⑥現実とモデルの比較 → ⑦実行可能で望ましい変更の合意。

## 道具（どう使うか）
- **リッチピクチャ**：状況の論点・関係・問題を"1枚の絵"で非構造に描く。関係者の視点を可視化する初手。
- **根本定義（root definition）**：「Y の手段で X を行い Z を達成する（do X by Y to achieve Z）」の形で、対象システムの目的と中核変換を言語化。
- **CATWOE**：Customers / Actors / Transformation / Weltanschauung（世界観）/ Owner / Environmental constraints の6要素で根本定義を点検。
- **概念モデル→現実比較**：あるべき活動モデルと現実を突き合わせ、"望ましく実行可能な変更"を合意する。

## 落とし穴（避けること）
- **ソフト問題をハード問題として扱う**：関係者の世界観（W）を無視して"正解"を最適化しにいくと、合意が壊れて実装されない。
- **問題を早く定義しすぎる**：複雑な状況を先に問題定義で固めると、真の論点を取りこぼす。まず状況を豊かに理解する。
- **ステークホルダー視点の欠落**：CATWOE の Customers/Owner/Actors を飛ばすと、実行者・受益者・所有者のズレが後で噴出する。

## 教材への落とし込み（どの枝を支えるか）
- **C-1b（初回90分でロードマップ確定）**：初回にリッチピクチャ＋CATWOE で顧客の状況と目的を構造化し、根本定義から"解くべき問題"を合意 → その上で⑥のイシューツリーで原子分解、という接続が自然。
- **B1（各コマ到達点）**：初回で"望ましく実行可能な変更"を合意する到達点の設計根拠。
- **F1（コマ間伴走）**：世界観・利害の継続的な擦り合わせ（別チーム開発の受け渡し）の裏づけ。
