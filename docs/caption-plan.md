# 字幕の分割：現状と、これから良くする案

2026-08-19。マスター指示「まず7割を解決して実機確認する。そのあとのより良くなる施策は案として記録しておけ」に対する記録。
判断の正は `docs/編集についての虎の巻.md`。ここは字幕の「どこで改行するか・どこでカードを切るか」だけを扱う。

---

## 問題は3つに分かれる（1つの道具では全部直らない）

| | 症状 | 現状 |
|---|---|---|
| **A** | 文字起こしに句読点が無い | **未着手** |
| **B** | 改行が語の途中で起きる（「い／ろんな」「ラッシュ／カット」） | **BudouX で大半を解消（下記）** |
| **C** | カードが助詞・接続助詞・言い差しで終わる | **未解決。A を解かないと解けない** |

---

## 入れたもの：BudouX（2026-08-19）

`video-shorts/src/vendor/budoux/`（Google, Apache-2.0, v0.9.0 の2ファイルを同梱。約28KB・依存ゼロ）。
`npm i budoux` は publish 事故で 60 パッケージ・約10MB を引くため使わない（`THIRD_PARTY.json` に理由を記載）。

`edit-job.mjs` の `groupIntoPhrases()` が、語を連結した文字列を BudouX に通して文節へ割り直し、
文字位置で元の語へ逆写像して時刻を戻す。行分割・カード分割はこの塊を最小単位にする。

**同時に捨てたもの**：LLM に「文と文節の切れ目の添字」を返させる工程（同日に一度入れたが実測で不採用）。
遅いうえに、複合語を割るなと指示しても「ラッシュ／カット」を割った。

### 実測（同じ素材「AI大学#3」・同じ指示・BudouX 前後）

目に見える改善：
- `ラッシュ／カット` → `ラッシュカットあれが`（1枚に収まる）
- `動画／編集`・`い／ろんな` は発生しない

客観指標（**同じ文字種の連続を分断した箇所**＝カタカナ語・数字・英単語の途中で切った箇所。議論の余地なく誤り）：

| | 切れ目の総数 | うち明白な誤り |
|---|---|---|
| 縦型 BudouX前 | 55 | 3（5%） |
| 縦型 BudouX後 | 56 | **2（4%）** |
| 横型 BudouX前 | 13 | 1（8%） |
| 横型 BudouX後 | 16 | **0（0%）** |

### 見積もりの訂正

着手前に「7割が直る」と述べたが、**その根拠にした測定は循環していた**。
「改行が BudouX の境界に一致するか」を数えており、**BudouX 自身が誤って割った場合を数えられない**指標だった。
上の客観指標が実態で、改善は「7割」ほど大きくない。

### BudouX が残す誤り（実測・句読点があっても起きる）

```
"はいじゃあ本番いきます321動画の編集って"
  → ["は","いじゃ","あ","本番いきます32","1動画の","編集って"]
"話題ごとのショート動画化です。"
  → ["話題ごとの","ショー","ト動画化です。"]
```

- **数字の途中で割る**（`321` → `32` + `1`）
- **カタカナ語の途中で割る**（`ショート` → `ショー` + `ト`）
- **話し言葉の冒頭で崩れる**（`はいじゃあ` → `は` + `いじゃ` + `あ`）

同じ弱点は `nkopikaso/AviUtl2-WhisperAutoSub` の作者も踏んでおり、changelog v2.9.10 で
「そういう」が `そう`+`いう` に割れる問題に特例パッチを当てている。

## これから良くする案（優先順）

### 案1【小・確実】文字種をまたがない分断を機械的に禁止する

BudouX の出力を後処理し、**境界の前後が同じ文字種（カタカナ・数字・英字）なら、その境界を消して隣の塊と結合する**。
上記の `321`・`ショート` は規則だけで消える。新規依存なし、実装は数十行、決定的でテストが書ける。
これは BudouX の弱点そのものを塞ぐので、**次に入れるならこれ**。

### 案2【中・本命】句読点を足して A を解き、C も同時に解く

C（言い差しで終わる）は**文の切れ目が分からない限り原理的に解けない**。実測でも、禁則の後処理だけでは
47枚→46枚しか減らなかった（送り先のカードが既に2行埋まっていて動かせないため）。

- `1-800-BAD-CODE/xlm-roberta_punctuation_fullstop_truecase`（Apache-2.0 / ONNX / **CPU 可** / 589,091 DL/月）。
  予測トークンに「。」「、」「・」を含む。kotoba-whisper が内部で使っているのもこれ。
- **Python 必須**（`transformers.js` は `BertJapaneseTokenizer` を実装しておらず、Node からは動かない）。
  このリポジトリは faster-whisper で既に Python を使っているので、工程を1つ足す形にはできる。
- **実装上の必須条件**：句読点を入れると文字数が変わる。**元テキストの文字オフセットを保ったまま挿入位置を
  管理し、word timestamp の対応を壊さないこと。** ここを雑にやると今度は時刻が壊れる。

句読点が入れば `endsSentence()` が初めて機能し、既にある `preferBreak` と `fixDanglingCardTails()` が効き始める。

### 案3【小・ダメ元】Groq の `prompt` に句読点付き例文を入れる

変更1行・コストゼロ。ただし OpenAI メンテナ（jongwook）自身が公式 Discussion で "a certain chance"、"nudge" と
書いており**保証は無い**。Whisper は30秒窓で処理するため最初の窓を過ぎると効果が薄れ、それを緩和する
`carry_initial_prompt` を Groq は公開していない。単独の解決策にはできないが、案2の前に試す価値はある。

### 案4【中】AviUtl2-WhisperAutoSub のアルゴリズムを読んで移植

`nkopikaso/AviUtl2-WhisperAutoSub`（4★ / 最終push 2026-08-05 / **ライセンス無し**）。
日本人が実機で作り込んだ規則がある：自立語で新文節を開始し、**付属語（助詞・助動詞・補助記号・接尾辞）は
前にくっつける**。**部分語タイムスタンプの区間割当**（文字数比でスケール）も実装されている。
**ライセンスが無いのでコードは流用できない。読んで再実装する参照物として扱うこと。**

### 案5【大】字幕分割まで返す商用 API へ寄せる

字幕分割パラメータを公式に持つのは3社だけ。

| | パラメータ |
|---|---|
| AssemblyAI | `chars_per_caption` |
| Speechmatics | `max_line_length`（既定37）/ `max_lines`（既定2） |
| Gladia | `maximum_characters_per_row` / `maximum_rows_per_caption` |

ただし**10社中1社も「日本語で1 word とは何か」を文書化していない**。既定値37はラテン文字前提。
採用するなら日本語音声で実際に叩いて目視確認が必須。

## 調べたうえで採らないと決めたもの

- **LangChain / LangGraph** — LLM 呼び出しの配管であって、トークナイザにも ASR 出力にも触らない。
  往復が減るどころか層が増える。`@langchain/core` 単体で 7.6MB。
- **WhisperX / stable-ts / faster-whisper への乗り換え** — 部分語は Whisper の**設計**（`tokenizer.py` が
  CJK を `split_tokens_on_unicode()` に通す。faster-whisper は同一実装）。どれに替えても直らない。
  WhisperX の日本語は**完全に1文字ずつ**（`LANGUAGES_WITHOUT_SPACES` で `per_word = text`）。
  stable-ts は **2026-05-30 にアーカイブ済み**。
- **形態素解析器（kuromoji.js / TinySegmenter / Sudachi / MeCab）** — どれも**文節を出さない**。
  kuromoji は辞書 18〜41MB。MeCab は Windows での別途インストールが必要。BudouX 28KB に対して得るものがない。
- **captacity / srt_equalizer** — **日本語では原理的に動かない**。captacity は `text.split()`（空白分割）で
  全文が1語になる。srt_equalizer の `split_by_punctuation` の正規表現 `[.,!?]` に「、」「。」が入っていない。
  ※ 2026-08-18 に「GitHub の実績実装を参考にした」として captacity の設計を移植したが、
  **その前提は日本語では成立していなかった**。
- **`gpt-4o-transcribe`** — 単語タイムスタンプ**非対応**（公式明記）。乗り換え先にならない。
